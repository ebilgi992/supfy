## Explicit non-bugs and unsupported claims

- No developer client ID/redirect registration is available. A new API/PKCE login cannot be invented, and successful API consent would not create the player's cookie session.
- External Google/Apple/Facebook browser authentication cannot automatically import cookies into the WebView. The current explanation is truthful; this limitation is not fixed by weakening TLS, copying cookies or spoofing an OAuth return.
- Spotify's public site owns catalog, library, account rights, queue and playable media. Native shells must delegate only supported actions and must not fabricate content/results.
- Music downloads/offline export are not implemented. Do not expose working-looking fake downloads or claim Premium/DRM circumvention.
- A bounded public OSV query is documented in `SECURITY_AUDIT.md`. Its empty matches and pinned dependency age do not establish the security of transitives, resolved Compose artifacts, Android OS or the installed device WebView.

## Closure rules

The implementation owner should append concrete fix paths and test evidence when closing Q-002 through Q-004. A source diff proves a change exists; fixture tests prove the covered behavior; only an actual authenticated device journey proves that account/device case. The user's 1027 success must remain recorded separately from new-build verification. Media/audio findings belong to their specialized review and final test report; this register does not mark them passed by inference.
