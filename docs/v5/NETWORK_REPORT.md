# Supfy V5 network inventory

Source review dated 2026-11-01. This inventories code paths in the native `base/` project. A domain literal or dependency indicates a reachable path, not proof that the domain was contacted. Runtime traffic, timing, payloads, installed extensions and a controlled-account session were **NOT TESTED**. No credentials or private traffic were captured.

## Modules and transports

| Module / subsystem | Transport and data |
|---|---|
| app + host-android | Android WebView loads the official Spotify player/login. The native host relays Connect control and media traffic using OkHttp/Cronet/platform stacks. Android MediaDrm handles protected playback. Android media session / Auto exposes metadata locally. |
| api-spotify | Bridge calls plus authenticated REST/GraphQL. Access/client tokens live in Gql memory; account credentials go to Spotify API targets, public CDN requests use a separate target class. |
| app media/lyrics | Media3/Glide, NewPipe/YouTube extraction, third-party lyric lookups and optional translation. Requests can disclose media title, artist, IDs, selected language and client network address. V5 ConsentPolicy requires a revision-matching user grant before each optional provider feature; prefetch skips ungranted services. |
| extensions | GitHub/GitLab/Codeberg discovery/package metadata plus granted network hosts. New packages are disabled until explicitly enabled against the reviewed SHA-256; changed versions need approval again. Extension runtime and external pages add conditional endpoints that cannot be exhaustively listed from built-in literals. |
| Cast / Connect | Remote device/session control and local LAN discovery/streaming; CastServer builds token-bearing `http://<LAN host>:<port>/<token>/...` URLs. LAN HTTP is a separate path from public HTTPS policy. |
| build tooling | Google/Maven Central/Gradle Plugin Portal/JitPack supply dependencies; Foojay may resolve JDKs. These are build-time supply chain endpoints, not evidence of app telemetry. |

## Credential and blocking boundaries

`Gql.rawTarget` accepts HTTPS and exact Spotify domain suffixes, separating authenticated Spotify account hosts from public Spotify CDN hosts. Extension-provided authorization, cookie, client-token, host, origin, referer and framing headers are dropped. Extension raw responses recursively remove known credential JSON keys and credential response headers; malformed/non-JSON/scalar response bodies fail closed to empty. Credential/login/OAuth endpoint requests, encoded credential paths/query names, user-info URLs and token service access are refused. These are bounded source rules, not proof that arbitrary remote responses cannot encode secrets under innocuous keys. This is source evidence of a boundary, not a runtime redirect/header-leak test.

Optional provider HTTP and extension HTTP/media/download/update fetches use HTTPS-only public-address checks. SafeNet's CheckedDns rejects private answers on the connection resolver; redirect following is disabled unless the caller validates each hop, and sensitive headers are dropped where the extension path changes targets. Update downloads additionally restrict GitHub redirect hosts. An extension authentication WebView has a separate per-extension profile, no app cookie or JavaScript interface sharing, denied Spotify hosts and HTTPS/literal-host checks. Its DNS resolution remains platform-controlled; this is not a DNS rebinding protection claim for that WebView.

The existing shared AdBlock host list refuses `adstudio-assets.scdn.co`, Google ad endpoints (`pubads.g.doubleclick.net`, `securepubads.g.doubleclick.net`, `googleads.g.doubleclick.net`, `pagead2.googlesyndication.com`, `imasdk.googleapis.com`, `s0.2mdn.net`) and selected audience trackers (`googletagmanager.com`, `google-analytics.com`, `scorecardresearch.com`, `fastly-insights.com`). `blockedPaths` is empty; the source deliberately leaves Spotify's own ad config/events and sponsored recommendation endpoints available. The WebView/player also modifies ad playback behavior. Runtime effectiveness and service consequences have not been verified on V5.

ControlRelay explicitly relays `*.spotify.com/melody/v1/msg/...` play reports, including playback-start/stream-verification and played milliseconds. Spotify may use these for account history and Wrapped. `melody/v1/time` and `melody/v1/license_url` stay with WebView. **Disabling native history/logging does not disable Spotify's server-side playback history or all telemetry.** Login, challenge, tokens, Connect and Widevine license traffic remain functional dependencies. A URL containing `log`, `event`, `ads` or `report` is not by itself proof of unnecessary tracking; classify the full host/path and its function.

No packet-capture claim is made. To validate the built artifact, use a disposable controlled account on an isolated device, record destination/method/status and coarse data classes, exercise sign-in/browse/play/background/reconnect/lyrics/video/extensions/update/Cast, inspect native and WebView routes, and redact secrets before retaining evidence. Successful desktop page loading or historical Supfy/Quantum captures do not demonstrate V5 DRM playback or network privacy.
